\# Freshservice Issue-Tracking Process



\## Purpose



Freshservice was used to create, assign, track, and resolve cybersecurity issues during the project.



\## Process Followed



1\. A Freshservice ticket was created before development started.

2\. The ticket included requirements and the expected result.

3\. The ticket was assigned to the Helpdesk Monitoring Team and Mohammod Kamal.

4\. The ticket began with Open status.

5\. A progress note was added when development started.

6\. The ticket number was referenced in Git commit messages.

7\. The feature was reviewed through a GitHub pull request.

8\. The ticket was changed to Resolved after testing and merging.



\## Issues Completed



\### INC-1: Log Analysis



The feature detects failed logins, malware alerts, and blocked connections in a sample log file.



\### INC-2: Vulnerability Assessment



The feature checks firewall status, multifactor authentication, password length, administrator-account settings, and automatic updates.



\## Cybersecurity Procedures



\- Fictional data was used for testing.

\- No real passwords or confidential logs were uploaded.

\- Each feature was developed in a separate branch.

\- Pull requests were reviewed before merging.

\- Identified weaknesses included clear security recommendations.
